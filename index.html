Part 1

Understand and direct AI

0:00–0:45 · Mental models, prompt refinement, verification

What these systems are, plainly

Genuinely useful for

  • Synthesising and comparing technical material
  • Drafting, transforming, and reviewing code
  • First drafts of documents and procedures
  • Planning multi-step tasks and driving tools

Fluent ≠ correct

  • Invents citations that look real
  • Silently uses the wrong units
  • Misses a physical assumption
  • Writes code with a subtle bug that runs

Delegate the work; retain responsibility for the judgment.

QuantityValueMeaning

Residuals dropped 6.9 (pressure) / 7.5 (streamwise) / 8.7 (turbulence) orders; the last 100 iterations moved CD by 0.14%.

Three checks — two pass, one fails

1 · Lift is believable ✓

Zero-lift ≈ −2°; a 2D section gains ≈0.11/degree → 0.11 × (2 + 2) ≈ 0.44. Measured 0.402 — within 9%.

2 · Drag is not believable ✗

L/D = 26.6. A clean NACA 2412 at this Reynolds number should reach 50–70. Coarse mesh + y⁺30 wall functions + fully turbulent model → roughly double the drag.

3 · One residual looks alarming — probably benign

The lateral velocity only dropped 1.1 orders. In 2D that component is ≈0, so its residual is numerical noise. Probably. I would hand that question to an engineer.

What this does not prove

  • 2D only — no wingtips, no spanwise flow
  • Steady — nothing about stall or separation
  • Fully turbulent — wrong near transition
  • One angle of attack — no lift curve, no drag polar
  • No mesh-independence study
  • No experimental validation
  • y⁺30 cannot support drag claims
  • The turbulence model is an assumption, not physics

"The AI drove a validated pipeline." Not "the AI did CFD."

Part 2

Engineering with AI

0:45–1:15 · Python, the Breguet range equation, and testing

Breguet range — idealised cruise

R = (V / (g·cm)) · (L/D) · ln(mi / mf)

SymbolMeaningUnit
Vtrue airspeedm/s
cmmass-based TSFCkg/(N·s)
L/Dlift-to-drag ratio–
mi, mfinitial, final cruise masskg

Why g? TSFC is per unit thrust, a force. Converting to per unit weight brings in g. Mixing conventions is the classic units bug.

Test case — and what to expect

VL/DTSFCmimfExpected R
230 m/s171.7×10⁻⁵ 50 000 kg40 000 kg≈ 5 233 km

With g = 9.80665 the exact value is 5 233.5 km. If you see 523 km or 52 310 km, stop — that's a unit slip.

Now introduce a bug

Change log(m_i/m_f) to log(m_f/m_i) → range becomes −5 233 km. Ask him to diagnose it before asking for a fix.

Four verification tests

TestQuestion
Dimensional consistencyDo the units reduce to distance?
Physical plausibilityCan positive fuel burn over positive range give negative range?
MonotonicityDoes raising L/D always raise range?
Independent calculationDoes a separate spreadsheet agree?

Passing tests proves the code satisfies those tests. It does not prove the model fits the aircraft or the mission.

Part 3

AI for the B&B

1:15–1:35 · Guest communications and operations

Pre-arrival email

The prompt must forbid invention

Warm, personal, under 180 words. Include arrival-time confirmation, the historic centre and Rio Pardo waterfront, Ilha de Atalaia, and an offer to arrange activities.

Do not invent facilities, check-in arrangements, restaurants, transport or booking details — use placeholders.

Then he adds the 20% that matters

Two details from the actual business: the property's character and one recommendation he personally trusts.

AI drafts 80%. The owner supplies authenticity.

Answering a negative review

"The room was comfortable, but check-in was confusing and we couldn't get a clear answer when we messaged the property."

  • Acknowledge without becoming defensive; thank them for the feedback
  • Mention the process being reviewed — do not claim it is already fixed
  • No excuses, no unauthorised compensation, no revealing booking details
  • 60–90 words · then ask for a warmer version and a more concise one

A practical verification framework

#CheckQuestion
1Verify the objectiveIs it solving the actual problem, or a look-alike?
2Verify assumptions and unitsAre definitions, inputs and constraints consistent?
3Test independentlyAnalytical estimate, known case, external reference, real records?
4Check the evidenceDo the citations and local details survive a source check?

Take-home: the AI field guide

Six ingredients of a prompt

  1. Role
  2. Objective
  3. Context
  4. Constraints
  5. Output format
  6. Verification

Five rules

  • Confident language is a claim, not evidence
  • Running code ≠ correct code
  • Verify facts at the source
  • Keep sensitive data out of unapproved tools
  • Human approval for consequential actions

Three workflows to learn first: research · engineering · operations

Three commitments for the next seven days

  1. One daily use — a real task, every day, for a week
  2. One engineering experiment — small, with a documented verification process
  3. One hospitality improvement — implement it and measure the time saved

Success is not how many prompts you write. It is a better result, less time, or fewer errors — without losing quality.
